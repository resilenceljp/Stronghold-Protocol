# 娱乐、无尽与服主监视台

本分支基于 LongQianChen 的 20 人版本，由 resilenceljp 维护。仓库：https://github.com/resilenceljp/Stronghold-Protocol 。上游作者、贡献者和许可证声明保留。

## 如何开始

在建房界面的「玩法模式」选择「原版模式」或「娱乐模式」，无尽在第二页娱乐规则中开启。单人和最多20人同盟均可使用。娱乐与无尽房以同盟密钥邀请，不参与快速匹配；本局选项在第二页准备界面由房主设置，开始策略选择后锁定；房主转让和断线重连不会改变已确认规则。房内每个真人只可操作自己的席位。

在第二页准备界面启用「休整期控制台」。进入休整期后点左下角按钮栏中的「控制台」：可按名称/ID搜索普通及精锐干员、装备和法术；点击＋获取；盟约页指定增加层数；等级页提升调度中心，资金页增加资金。不设每回合或全局调用次数限制。手牌/临时区容量、自动合成、准备状态、淘汰与阶段限制继续生效。控制台不会在作战期修改战斗输入，也不能操作其他玩家或复活已淘汰玩家。

控制台获取的干员不占共享干员库存；免费装备及由其参与合成的装备不占共享装备库存。原版房拒绝控制台请求；关控制台的娱乐房也拒绝请求。娱乐结果不写入原版胜率/认证统计。

## 9999层

娱乐和无尽房各盟约的层数上限为9999；原版仍为999。沿用原有逐层属性增益、层数触发和激活条件，仅改变上限。休整期、战斗实时模拟、客户端结果校验、暂存战绩视图与结算使用同一房间上限。层数达到上限后新增收益为0，已禁用的盟约不会因控制台而自动激活。

## 无尽模拟 AC-∞

按用户选择，敌人生命/攻击/防御倍率为 `min(10^12, 1.1^(回合-1))`：第1回合×1，第2回合×1.1，第15回合约×3.7975。保留敌人技能、移动速度、原有装备/盟约规则。倍率随 BattleSpec 发给浏览器，领袖生命池和中途退出缩池也使用相同倍率。

- 前14回合使用险境模拟的战役模板，第14回合为最终攻势。单人也固定14回合。
- 赢得最终攻势后直接进入第15回合，不进入隐秘核心；失败仍正常结束。
- 第15回合起循环第8–13回合的普通波次、敌人类别和时限，使用当前无尽回合的倍率，不生成空波次；队伍和个人经济、阵容、层数、LP继续保留。
- 从险境的8张战场中按原有种子随机选1张，全局保持该地图。后续每回合照常休整、战斗和联防，直到全部淘汰或退出。
- 七级商店为独立准备页开关，6→7基础升级价20；第7级在第6级基础上额外一个干员槽与一个装备槽，其他刷新、冻结、购买规则不变。关闭时无尽也只有6级。
- UI和监视台区分娱乐、无尽以及控制台开关，无尽回合分母显示∞。

以上都是分支新增的娱乐规则，非官方原玩法。截图未指定的波次循环、7级价格与特殊道具集合为 `[ASSUMED]` 实现选择。10^12是防止浮点溢出的数值保护，在约290回合之后倍率达到保护上限；没有人为设置最大回合数。

## 内置监视台

`monitor/` 独立存放监视台UI、启动脚本、安装工具和 boot v7/helper。可双击 `monitor/启动监视台.cmd`（以实际目录内文件名为准），或运行 `npm run monitor` 后访问 `http://127.0.0.1:3010/`。默认读取游戏3000和本地管理员3001；游戏换端口时在监视台设置相应端口。

游戏 boot 已内置本地监控与显式消息管理员接口；不必重复安装boot。只向127.0.0.1开放，不能把管理端口穿透给玩家。控制台是可选游戏机制，监视台是本机服主工具，两者权限独立。监视台本身可以单独停止，不影响对局。

支持20人分组对照表、自动刷新保留滚动位置、休整结束的阵容/头像快照、商店效果与经济/LP/战绩、房间时间及连接诊断。SakuraFRP剩余流量读取本机已有启动器凭据，60秒刷新，统计账户所有通道；游戏TCP计数不等于平台计费。没有凭据时只显示不可用。发布包不含 `monitor/data/`、令牌、私人配置和日志。

## 安装与更新

源码运行：Node.js22或24，`npm ci`、`npm run setup`、`npm start`。已有游戏素材可沿用本机素材目录；不要把游戏素材提交到Git。测试使用3020/3021，与正式3000/3001隔离。

当前正式服务器不会被自动替换或重启。应用新游戏代码时等本局结束，完整备份原目录，再部署新分支；游戏更新包校验可能拒绝改过boot的目录，源码部署不依赖旧便携包的清单。每次监视台更新使用 `monitor/Package-Update.ps1`，同步boot、helper、版本ZIP和latest ZIP到 `D:\Stronghold-Protocol`。

## 第二页规则与藏品（fun.2）

娱乐与无尽共享第二页规则。可选控制台、官方/满练度、8/12部署位、额外起始资金与藏品开关；规则变化须全员重新就绪。藏品池可勾选排除，集中目录为shared/relics.js。每轮本人无漏怪三选一，三轮连续漏怪触发逆风补给及下一回合2点LP护盾。17件基础藏品，同名不重复、仅本局有效。fun.4/5整备区固定22格两排11格，fun.6改为准备页可选。

fun.5 满练度由官方角色、技能、模组表生成独立文件，六星E2 Lv90、其他干员按官方最高等级，满信赖与潜能。标准模式数据保持原样。完整边界、概率假设和验证见[DEV-20261013-02](development/records/2026-10-13-02-fun-rules-relics.md)。


fun.3 布局、七级普通商店槽与手机精简素材说明见[手机与布局更新](FUN_MOBILE.md)。

有限娱乐局正常完成Boss挑战后会弹出无尽投票，全体真人同意才继续；拒绝、退出或60秒超时即保留胜利并结束。开局直接无尽不再占单独模式按钮。控制台警告：该功能将极大降低游戏体验和乐趣。监视台支持服主消息与当前对局聊天。详情和数据来源见[fun.5记录](development/records/2026-10-13-04-fun5.md)。

## fun.6 扩展整备区

准备页默认关闭：整备10格、临时5格。开启后为两排各11格整备，以及最底部一排11格临时区；商店可能遮挡区域，收起后查看。只有INFO_CHECK允许改动，修改会取消就绪。普通模式数量不变。选中框、出售、拖放、临时区标记都采用同一坐标。扩展休整使用程序化棋盘为第三排留位，左右半场对称；实际战斗仍使用原版场景和坐标。

fun.7替代原10%无尽规则，详细规则、控制台边界和结算图片见[DEV-20261014-02](development/records/2026-10-14-02-fun7.md)。
