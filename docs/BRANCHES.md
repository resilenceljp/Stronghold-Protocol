# 来源分支与版本记录

本仓库是独立导入仓库，GitHub 的 Fork 同步按钮不能同时处理两条不同来源。使用 Git 的共同历史合并，并分别保存上游原样快照。

| 分支/标签 | 用途 |
|---|---|
| `feat/IncreasePlayerCapacity` | 默认展示页与20p核心，保持独立来源；同步工作流入口 |
| `upstream/20p` | LongQianChen 的 `feat/IncreasePlayerCapacity` 原样镜像 |
| `upstream20/v版本-SHA` | 每次20p同步的固定快照 |
| `upstream/original` | sganggs 最新正式 Release 的原样镜像，不追开发中的 master |
| `upstream-original/v版本-SHA` | 原版正式发布快照 |
| `feat/entertainment-endless` | 我们实际使用的娱乐扩展开发分支，包含原版0.2.5和20p功能 |
| `backup/fun3-before-original025` | 合并0.2.5之前的功能备份 |
| `v0.2.5-20p-fun.4` | 原版0.2.5合并节点 |
| `v0.2.5-20p-fun.5` | 本次控制台布局、无尽投票、七级商店、满练度与监视台消息版本 |

## 更新方法

Actions 中有两个同步入口：「同步原版20p到独立分支」和「同步最原版正式版到独立分支」。它们每日检查，也可以手动执行；只更新对应上游分支和快照，绝不自动覆盖我们的游戏功能。

在开发分支手动合并镜像，解决冲突后跑测试与战斗回归，再更新 `UPSTREAM.json`、版本号与开发记录。版本的 `0.2.5` 来自**已合并**的最高内容基础版；`20p-fun.5` 表示我们第五次扩展修订。只拉取而未合并的上游，不计入已包含版本。

当前已包含：原版 `v0.2.5`，提交 `cf7a9400270d5aa79b2e601e405dab782e25f120`；20p `v0.2.4-20p.5fix`，提交 `6a2b72bb97d1469194fd758b3001017a632ce23f`。这两条 SHA 是版本证据，不能用相似的版本名称代替。

部署前备份。服务仍有对局时不替换运行中的游戏代码；本机更新暂存到下一次启动再校验、备份与应用。
