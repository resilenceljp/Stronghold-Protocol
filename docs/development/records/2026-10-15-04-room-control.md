# fun.12 / UI 2.2 / boot v11：本局干预

仅本机服主通过监视台的房间干预窗口执行。原版默认规则保持；下列行为必须由服主显式点击确认。
所有写操作检查Host、同源Origin、专用转发头和请求大小；校验room.createdAt、matchCount及round，
拒绝旧房间、旧对局或旧回合请求。动作写入监视台事件，并向房间广播服主干预提示。

- 牌库：信息确认/休整可按A–E组或全部组、干员/装备、品阶和具体种类设置总份数0–10000。
  总数不能低于已持有份数，先校验所有目标再修改，保留cap-left=held；不清空玩家卡牌，
  不动禁用牌、自选私有库存、已展示商品。仅本局生效，重刷重建卡池后重置。
- 真人托管：信息确认/休整切换现有autoplay，不改变真人席位身份。
- AI：休整可暂停自动逻辑，后台购买、刷新、升级、冻结、移动、出售、装备和准备。
  使用原有意图校验和资金扣费，不赠送资金或物品；不延长休整倒计时。可恢复AI自动。
  等待房间可直接移除AI；局内仅休整可移除，走原有淘汰/卡牌归还逻辑，不重新分组。
- AI交接：后加入者先在线，支持大厅或本房观战；严格素材准入时须先成为本房观战者。
  只在休整交接活着的AI，不能覆盖正在其他席位对局的真人，不复活被移除AI。
  保持AI原playerId、棋子uid、资金、练度/技能、商店、策略、层数、已得藏品与固定组。
  新玩家保留自己的连接令牌，原大厅/观战ID移出索引，新ID收到welcome和完整重同步；
  保留协商的紧凑协议版本，刷新/断线后仍回到继承席位。不会把个人调配覆盖AI已有阵容。
  服主可在监视台人工控制AI而不离开自己的玩家席位；交接是另一项需选定新玩家的操作。
- 压力：0.1–20的额外乘数，下一回合开始应用，乘原难度或无尽累计倍率；
  HP/ATK/DEF同乘、移速不变，Boss共享血池同乘且无尽下不重复计算。设为1在下回合恢复。
  不修改正在进行的战斗；当前战斗阶段拒绝干预。只影响此房此局。

实现：独立compat/room-control.js；游戏侧仅增加人工AI暂停、接管welcome标记和压力消费点。
旧版游戏不支持这些消费点时不宣告roomControl能力，安装boot v11不能单独替代fun.12游戏代码。
上游#605保持只读贡献，不包含这些功能。源码与ZIP不含个人设置、流量日志、房间记录或凭据。

验证：库存守恒及跨组隔离、减库存拒绝、阶段与旧轮次拒绝、压力延迟及Boss单次倍率、
AI托管/人工购买/移除归还、等待室移除、观战者交接、紧凑协议重同步、重连及战斗归属。
真实浏览器验证牌库、压力、AI购买、席位交接与刷新恢复；普通池和Boss原有测试保持通过。
